## 一期目标

个人通过组合好的 Flow 生成一个自媒体 Bot，Bot 去执行 Flow，产出一条 vibe 知识大赏视频。

成功不是“出了一条片”，而是：同一套节点、工具、质检、审批、预算、版本机制，不改底层就能再出下一条片；下一条片只换选题、文案与参数。

一期对外使用的作品交付物只有三样：待发布无声成片（MP4）、备选标题、标签。事实依据、HTML、质检结论和版本记录是平台内部必须保存并可查看的过程产物。发布、选标题、定时间、加 BGM 由 zz 在抖音自行完成，不在 Flow 内，不在平台内。

## Bot 是什么：定义与绑定

一个 Bot 的目标定义：一个身份、一个默认 Flow 执行绑定、一份独立记忆和一套执行记录。身份与绑定已有基础；独立记忆及作品管理需要在本期补齐。

- 身份：名字、头像、systemPrompt、默认模型。
- 执行绑定：默认绑定已发布的 FlowVersion。修改执行语义后发布新版本，并明确更新 Bot 绑定；新任务使用新绑定，旧任务保留锁定的定义与输入。发布和改绑的失败、回滚均须验证。
- 记忆：先保存用户与 Bot 范围内的选题偏好、风格和固定要求；跨会话可读取，修改有版本，可回滚。事实依据、HTML、成片及其修订存为作品记录，不全部塞进聊天摘要。
- Bot 间默认隔离；用户与 Bot 的数据归属必须明确。一期不新增群聊协作，未来共享上下文时再定义具体范围，不能把“被点名”直接等同于开放全部记忆。

一期只交付一条业务 Flow：vibe 知识大赏视频。绑定多条 Flow 是后续扩展方向，当前 `defaultFlowVersionId` 单一绑定与预留 subagent 接口不代表多 Flow 调用闭环已经实现。

## 使用流程：日常只跟 Bot 聊天

1. 用户在聊天里对 Bot 说意图，例如“今天做一条 vibe 视频”。
2. 识别聊天、制片或需要澄清的意图；明确制片意图后才进入昂贵步骤。推荐一期在绑定 Flow 中用结构化判断与 condition 显式分支，不增加独立路由服务；这是待实施方案，不是当前已有行为。
3. Bot 按 Flow 图执行：选题查证、文案、分镜、渲染、质检、交付确认。
4. 用户在聊天里看到两层可视化：执行链路（跑到哪一步、哪一步失败），以及 Bot 产物（成片预览、选题与事实依据、版本记录）。
5. 人工审片在 Flow 外完成。zz 审成片、标题、标签，平台保存被审作品版本、结果和修改意见，确认后自行发布。

制作者流程与使用者流程分开：制作者在管理后台画布上编辑 Flow，可借助现有 AI 工具起草，但发布前必须校验、试跑并由人审阅；一期不另外建设完整的 AI 画图助手。使用者在聊天里用 Bot，不画布。

交付端建议：优先 Sola 桌面端使用、管理后台编辑 Flow，不同时扩展小程序与 H5 的新产物界面。该选择待 zz 确认，不阻塞前两阶段的渲染工具化。

## vibe 视频 Flow：端到端

目标流程只用现有通用节点类型，不新增领域节点。下表描述工具化及 Bot 基础补齐后的流程；阶段 2 验收仍使用现有 render 节点。

| 阶段 | 节点类型 | 做什么 | 输出产物 | 门 |
|---|---|---|---|---|
| 选题与查证 | agent | 按选题标准挑热点事件，查证事实与来源 | 已核验事实清单，带来源 | 事实无来源不得进入文案 |
| 文案 | agent | 写解说词与字幕文案，数字必须有来源，不得编造 | 解说词、字幕文案 | 数字无来源阻断 |
| 分镜与 HTML | agent | 按帧规范生成分镜 HTML，画面约 5 到 6 秒一切 | 版本化 HTML，HTML 引用 | HTML 须过机器质检 |
| 渲染 | agent，配置待实现的 render 工具组 | 按确定参数调用渲染工具，从真实结果取得对象路径 | 可信成片路径与对应作品版本 | 输入、调用与返回结果由运行时校验，失败原因进 trace |
| 机器质检 | agent 调质检工具，evaluate 辅助评审，condition/loop 控制分支 | 检查 HTML、抽帧与内容依据，输出结论与返工意见 | 规则检查报告、模型评估、放行结果 | 硬性检查失败不得被模型评分覆盖；返工耗尽也不得放行 |
| 人工审片与交付 | Flow 外确认 | zz 审成片、标题、标签，确认后自行发布 | 待发布成片 | Flow 内不设发布动作；一期不新增 approval kind |

说明：阶段名称不能代替节点指令。当前通用 agent 没有独立指令字段，需先补齐指令配置或注册相应技能；每段指令必须真正进入执行输入并可追溯。文案与分镜节点不分配渲染工具；渲染节点职责限定为调用渲染能力。是否实际调用、是否重复、参数是否匹配、输出路径是否真实，不能只靠 prompt 约束。现有 agent 只声明 `text` 输出，工具结果进入下游的可信契约需在阶段 3 落实。

## vibe 规格：已定部分

- 形态：竖屏 1080×1920，约 1 分钟，纯画面无音频；字幕按解说词写；BGM 由 zz 发布时自加，不进 Flow。
- 节奏：一天一条；开头先抓人；画面约 5 到 6 秒一切；内容更丰富、节奏不拖拉。
- 选题：优先 24 到 48 小时全网热点事件（大厂新品与发布会、重大安全事件、社会级话题），原理挂在事件后面讲；学术论文只有本身已成网络热点才入选；常青冷知识只留 1 个备选；接地气优先（手机、汽车、电视、购物、游戏、日常消费），纯天文硬核不入选。
- 内容：原理正确、简单易懂、图文并茂；数字必须有来源，不得编造；无来源的数字不得进入文案。
- 历史材料记载：首条 Roadster 倒挂原理视频发布 3 小时播放过万。本次仓库审查未独立核验后台数据，不作为一期能力证明或播放量承诺。

待定资产，不在本文件里编数字：字号与字重、配色 token、安全区、字幕带位置与样式、标题卡样式、转场词汇。这些写进帧规范资产，Flow 与模板引用它，不各自现编。

帧规范同时必须包含执行契约：`window.renderFrame(timeSeconds)` 按给定时间推进画面，资源按现有沙箱要求内嵌，字体就绪后截图；不能依赖外部网络或真实时间碰巧推进动画。HTML、模板、字体及帧规范的版本必须能定位。

## 一期功能清单

### 聊天与 Bot

- 一个自媒体 Bot 聊天入口：一个单聊会话绑定一个 Bot，同一 Bot 可开多个会话。
- Bot 身份与默认 Flow 绑定：身份、默认模型、绑定的 vibe Flow 版本。
- Bot 独立记忆与作品记录：跨会话读取选题偏好和风格，事实依据与成片按作品保存、按修订追溯。
- 聊天与制片的意图判断：结构化输出闭集与显式执行分支；模糊请求先澄清，重复请求有明确处理。
- 基础聊天能力必须保留：未进入制片分支时正常聊天，不因绑定视频 Flow 就每次生成视频。

### 执行与版本

- 区分 Flow 定义版本、任务执行轮次、作品修订版本、偏好版本与工具版本；修改作品不等于发布新 Flow。
- Flow 的执行指令等语义修改后发布新版本；Bot 人设及外部资产不自动受 Flow digest 保护，任务需锁定有效输入并记录依赖版本。已有节点输入快照不能替代整个任务的依赖约束。
- 人工审片结果绑定具体作品修订，返工后旧结果不自动沿用。图的发布审阅、运行中的工具/计划审批、成片审片分别记录。
- 执行记录与 trace：每一步状态、产物关联、失败原因可查；展示的产物来自真实记录，不从模型文本猜测。
- 恢复与复用：断线回看、同任务失败恢复、发起新作品和人工要求返工分别定义。不得把 SSE 重连变成重复制片；涉及不可确认的外部写入时允许明确失败，不承诺任意故障都自动恢复。
- 可复现指可追溯配置、输入及执行事实，并能用同配置再次运行，不保证模型每次生成逐字或逐帧相同内容。

### 可视化：两层

一期先做最小可用的两层，第二层细节后面再定。

1. 执行链路可视化：步骤状态、进行中与失败位置、每一步的产物链接。
2. Bot 产物可视化：一期最小集是成片预览、选题与事实依据卡片、版本记录。

一期不承诺粉丝与播放量接入。第三方自媒体数据目前拿不到，短期只展示自有选题与风格类数据。健康助手 Bot 的图表、自媒体 Bot 的粉丝播放数据等扩展，是第二层的扩展方向，不是一期功能。

### 渲染：直接工具化，再整体验收

当前代码仍使用 render 节点。目标为经 CapabilityRegistry 注册的 `renderHtmlToVideo` 工具；工具化尚未实现，不能描述为已可用。执行顺序见阶段 2 与阶段 3。

- 保留：Activity 内的 Puppeteer 逐帧截图与 FFmpeg 编码逻辑、COS 存储服务、Docker 沙箱与字体与隔离探针、COS 幂等与故障恢复逻辑。
- 改成：工具输入与原配置同义（HTML 引用、宽、高、时长秒、帧率）；引用必须由可信执行上下文解析。工具返回真实 COS 对象路径，视频字节与帧图不进 Flow 状态。
- 保持：长超时、心跳、取消、临时资源释放、输入摘要校验及稳定幂等身份。普通 agent Activity 与当前渲染 Activity 的超时配置不同，不能仅把函数挪进工具就认定运行语义保持不变。
- 工具实现复用 html-render 模块与 COS 服务；明确由哪一层持久化调度和恢复长任务，不在模型执行循环里直接引入无法恢复的 Puppeteer 工作。任务需要记录并约束实际使用的工具实现版本，单独写一个版本号不能保证旧实现仍可执行。
- 退出旧入口：工具路径验证通过后，再按存量清单停止新增旧 render Flow；历史工件、任务排空或迁移完成后，移除 render 专属配置与执行分支。不能只迁草稿就删除已发布工件仍依赖的执行能力。
- 契约版本：先盘点 v13 是否已持久化、发布或进入运行。不得直接把 schemaVersion 回退来删除历史；不为此次改造建立长期双轨，过渡范围与移除条件必须明确。

历史材料记载的最小 Flow 任务 `cmvtqtssx0007c38xwfwrt7v1` 产出 60 秒成片（1080×1920、30fps、1800 帧），本次未重放验证。它不能证明工具路径。工具化使用新任务验收，绑定当次完整代码内容摘要；形成提交后补记对应 SHA。

### 质检

机器质检分为工具检查、模型评审与硬性放行。当前 evaluate 不调用工具，也不自动阻断下游；工具由具备对应能力的 agent 调用，可信检查报告必须进入可查询的产物记录。后续显式 condition 检查放行条件，loop 只管理有限返工。

- 契约检查：HTML 引用存在且为当前版本；宽、高、时长、帧率在约定范围内；渲染输入输出 schema 通过。
- 画面检查：抽帧采样（开头、中间、结尾与字幕密集处至少各一帧）；文字不溢出、不重叠、对比度可读；画面切换节奏符合帧规范。
- 内容检查：字幕与解说词一致；数字与事实清单一致；事实关联来源 URL、发布时间/事件时间、检索时间和支持该结论的内容。来源存在不代表支持该结论；无法查证时明确不通过或交人工核验，不标记为已核验。
- 质检工具要能拦住构造的坏例，例如文字溢出、缺来源，否则不算质检做完。
- 放行检查：规则检查失败、模型判为不通过、检查报告缺失或返工次数耗尽，均不得进入“合格待审片”。loop 的 done 分支必须再次检查是否合格；模型不能覆盖硬性失败。
- 抽帧只能证明采样范围内的检查结果，不能宣称视频每一帧都无问题；人工审片继续保留。

人工审片在 Flow 外：zz 审成片、标题、标签；不通过则关联原作品和修改意见发起返工，产生新的作品修订。记录新旧修订关系，不直接篡改已经结束任务的节点输出，也不自动继承旧审片结果。

成本记录：每条作品必记模型调用与 token 用量、渲染耗时、失败重试和人工审片时间。供应商没有真实用量时标记估算，金额换算须有价格依据，未知项不得当作零成本。按合格成片归集失败尝试的成本，检查高成本样例；样本不足时不编造可靠的尾部分位数。阈值待试跑取得数据后由 zz 定。

## 一期不做

- 音频与 BGM 合成、自动发布、抖音运营调度。
- 生视频（模型直接生成画面）、小说、短剧、完整剪辑器、分布式渲染。
- Bot 市场、多业务首页、群聊多 Bot、定时任务、主动执行。
- 第三方粉丝与播放量数据接入。
- 新增领域节点类型、新增 approval kind、全局预算调整、无关的认证与模型与凭据改动、生产部署、通用记忆平台。

允许为本期明确缺口补通用节点指令、可信工具结果和最小数据契约。数据库迁移不预先承诺为零：渲染工具化原则上不扩 schema，Bot 记忆与作品版本在数据设计后决定。若需要迁移，只修改 schema，由用户本地执行 `pnpm --filter ./apps/api run db:migrate`；交付时提供 migration name、影响与回滚说明，AI 不手写 migration.sql、不代跑迁移。

### 阶段 1：分支与改动归集

1. 固定当前 HEAD、工作区补丁、未跟踪文件清单及内容摘要，保护用户已有修改；不使用 reset、clean、强推来制造干净工作区。
2. 逐分支、逐文件核对有效差异。旧分支可能包含后来替代的修复，整分支合并或盲目 cherry-pick 会把快照、重复代码与运行材料带回。
3. 将改动标记为渲染功能、相关回归、用户其他工作、验收证据和可清理材料；这一步是归属标记，不授权删除。特别检查认证、移动端配置和锁文件混合改动。
4. 以 `feat/agent-flow-render` 作为当前归集入口，补齐确有遗漏的修复；分支的数量不等于未完成需求的数量。不为了归集再建立一组平行业务分支。
5. 给每个 `agent/*` 分支和自动 stash 留下去向：有独有改动则保留待处理，代码已覆盖则保留必要证据后列为清理候选。

本阶段产物：一份最小差异与保留清单、可恢复材料、正式代码范围。整体验收和用户要求的正式提交完成前，不删除承载恢复依据的分支或 stash。

### 阶段 2：渲染工具化

本阶段直接把渲染能力改造为经 CapabilityRegistry 注册的 `renderHtmlToVideo` 工具，不再对现有 render 节点做单独前置验收。工具化是独立可 review、可回退的增量。

1. 先补通用 agent 的独立指令能力或落实技能注册，贯通契约、校验、编译、管理端和执行快照；节点描述不能充当执行指令。
2. 在 CapabilityRegistry 注册渲染工具及工具组，明确参数 schema、权限、资源与成本限制、失败语义和回归用例。
3. 定义可信 HTML/作品引用与工具调用身份；区分同调用重试、再次渲染和作品返工。下游产物引用取自已验证工具结果，不能信任模型复述的路径。
4. 落实长任务调度边界，保留超时、心跳、取消、幂等及恢复能力；证明普通 agent 执行超时不会截断渲染。
5. 盘点已保存 v13 定义、已发布版本和在途任务；创建新的工具版草稿/发布版本，不原地篡改历史工件。工具版可用后停止新增旧入口，待存量处理完成再移除旧支持，记录退出条件。

退出条件：工具路径接入完成、可被新任务调用；调用与产物可追溯，旧工件无悬空依赖。工具化未通过时可回退，不宣布一期已经具备工具化能力。

### 阶段 3：整体验收

工具化完成后，对工具化的 render 链路做端到端整体验收，覆盖管理端、Activity、COS、真实成片和异常处理。发现问题回改工具化实现，直至达标。

| 检查面 | 必须验证的行为 |
|---|---|
| 管理后台 | 添加节点、参数与引用校验、保存、刷新回显、导入导出；错误输入不能伪装成保存成功 |
| 真实成片 | 新任务生成 1080×1920、约 60 秒、无音频 MP4；下载后检查媒体信息并实际播放，抽看开头、中间、结尾 |
| 正常链路 | FlowVersion、节点执行、渲染进度、COS 对象和最终任务状态可关联；真实运行使用正确的编排/Activity Worker |
| 失败与取消 | 缺少帧接口、无效 HTML、编码或上传异常、取消均有明确状态；浏览器、FFmpeg 和临时目录正确释放 |
| 重试与恢复 | 已完成结果不重复执行；Worker 重启后恢复或明确报错；COS 不确认写入不能通过删声明强行重试 |
| 隔离与环境 | 浏览器沙箱、外部请求与本地资源访问限制有效；记录实际操作系统、CPU 架构、镜像和字体，不把单一环境结果推广到生产 |

验证按改动风险执行：API 单测及构建/lint、管理端类型检查/lint/构建及关键交互、Compose 配置回归；共享类型或编译链路变化时补移动端类型检查与小程序构建。浏览器隔离使用已有 `apps/api/scripts/html-render-security.spec.cjs`；需要构建后执行，真实浏览器/FFmpeg 缺失不能标成通过。测试命令以对应 package.json 和就近 AGENTS.md 为准。

真实链路运行在用户授权启动的开发栈中，不在本次文档修改时自动启动服务或调用真实模型/COS。宿主机 API 构建可能影响开发容器 dist 布局，验证前后要检查并按项目约定恢复运行环境。

退出证据：完整代码内容摘要、FlowVersion/digest、新任务 ID、环境、COS 对象 key、成片摘要与媒体信息、关键检查结果及未覆盖项。工具路径到真实成片已验证，调用与产物可追溯，旧工件无悬空依赖。未提交时明确标记工作区基线；用户明确要求提交后，按逻辑拆分提交并补记 SHA，业务无关改动不夹带。

本地验收、Git 交付和生产就绪分别记录。push/CI 阻塞不伪装成本地渲染失败，本地可用也不代表已推送、已通过真实 CI 或可生产部署。

### 阶段 4：Bot 最小闭环

前置：工具路径可用，并在界面实施前确认首期交付端。按阶段 2、3 结果选择最小实现，不重做现有聊天、trace 与审批组件。

- 意图与执行：同一个 Bot 既能普通聊天，也能明确启动制片。建议在绑定 Flow 内显式分支；若改为默认聊天 Agent 调用 Flow，须另列调用、取消、恢复与版本锁定工作，不能假定 subagent 已实现。
- 发布与绑定：明确发布新 FlowVersion 后如何更新 Bot；失败和回滚不留下失效绑定。冻结任务有效人设、模型选择和必要资产/工具依赖，验证修改配置不会改变已启动任务的约束。
- 最小数据：用户/Bot 范围内的偏好及修订，作品及其修订、事实来源、HTML/视频引用、Flow/工具/帧规范版本、任务关联、质检与人工审片记录。先确定读写与归属，再决定是否需要 schema 迁移，不把节点 scratch 当作长期业务数据库。
- 最小展示：聊天入口、执行状态、失败原因、成片预览/下载、事实依据、修订列表与审片反馈；补齐加载、空态、错误、重试或重新发起入口。
- 恢复与返工：页面重开能找回任务和作品；“重连查看”“恢复原任务”“修改后再生成”使用明确语义，不制造重复任务或覆盖旧作品。

退出条件：一个 Bot 的聊天、制片、查看、跨会话偏好和有版本的返工可操作，作品不只存在于临时链接或聊天文本中。此时可用最小验证内容验收入口，不能把它当作完整 vibe 内容质量验收。

### 阶段 5：vibe 制片流程

1. 固化帧规范和模板版本，明确字体、字幕区、画面节奏、时间接口与资源限制。
2. 实现选题与查证，补当前摘要搜索不足以支撑的时间和来源记录；无可靠来源就不进入已核验事实清单。
3. 串接文案、分镜、HTML、渲染与质检，明确每步输入输出；备选标题与标签也关联作品修订。
4. 使用构造坏例验证缺来源、文字溢出、渲染失败、检查报告缺失和返工耗尽；不能只跑一条成功路径。
5. 人工审片在 Flow 外记录；不通过时携带明确修改意见产生新修订，不能默认继承旧结果。

退出条件：新任务完整产出目标无声成片、标题与标签；来源、HTML、检查报告、版本与 trace 可查；不合格作品不会被标为可交付；zz 能查看并记录审片结论。

### 阶段 6：连续使用验收

前置：完整 vibe 流程通过。试用前确定批次规模、成本/耗时上限、可接受失败率和人工介入范围，不在观察结果后反向修改通过标准。

- 固定一版 Flow、工具与帧规范，完成多个不同选题；正常使用只更换选题、文案和允许的参数，不靠临时修改底层代码救场。
- 记录合格作品比例、失败位置、模型/渲染/重试成本、人工修改次数与时间，检查高成本样例和风格漂移。
- 覆盖来源不足、渲染失败、质检不通过、取消、重开查看和人工返工，确认状态与历史记录一致。
- 与当前人工或 agent 加 skills 的实际制作方式比较，判断是否减少重复配置、排错与修片成本；不凭 trace 或节点数量宣称差异成立。
- 发现必须修代码的问题时标记本轮失败；修复后生成新基线再跑受影响验收，不把不同版本的结果混成同一批稳定性证据。

一期完成条件：同配置可重复完成不同选题，质量门真实生效，作品可追溯且人工可审，成本与介入记录可核对。没有真实连续使用证据时只标记“单次流程跑通”，不扩展为“稳定日更”。

## 风险与遗留：区分代码事实与待复核历史记录

- 历史材料称 Linux 仅 arm64 小样通过，amd64 与生产 SYS_ADMIN 策略未验收；阶段 2 重新核对实际部署目标，不能关沙箱绕过。
- 历史 Temporal 收尾 SIGSEGV 与 sticky-cache 问题本次未重新复现；若影响当前任务结束或恢复，列为阶段 2 阻塞，否则保留明确适用环境，不能宣称已解决。
- 当前 COS 持久化声明机制存在“声明后 PUT 前退出无法自动恢复”的边界；不能删除声明或到期重发。Worker 必须使用同一业务 DB，升级前处理旧写入者，验收明确错误与恢复操作。
- 历史 push 403 的原因尚未在本次审查中核验；实际 Git 交付时核对 remote、失败响应、执行身份与网络路径，不输出凭据，不擅改凭据。
- CI 当前只有占位作业，workflow_dispatch 能触发但不验证构建；后续如启用真实 CI，单独记录实际执行的代码 SHA、命令与结果，不能把占位成功当构建通过。
- 不沿用历史“38 文件 tree”或旧全绿结论；以阶段 2 最终文件清单和内容摘要为准。已有 lint 警告与新失败分别记录。
- 当前正式归集入口为 `feat/agent-flow-render`，已不在 main 分支。原材料记载管理后台 5273、API 3000；真实验收前核对现有进程与入口，不擅自另开一套端口规避问题。
- `.multica` 证据可能存在于快照分支而不在当前工作区；不能按目录暂时不可见判定证据丢失或无用。不自行清库、清 COS、清镜像；历史任务与 NodeState 声明保留，删除仅覆盖确认清单。
