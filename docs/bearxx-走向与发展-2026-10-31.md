# Bear-xx 项目走向与发展

日期：2026-10-31
来源：本聊全部讨论汇总，包括 zz 的纠正、lyk 与陈伟正 2026-10-31 方向对齐会纪要、另一模型的独立判断、以及 100+ 开源项目逐仓库页调研。
状态说明：本文区分三类口径，读的时候不要混在一起。

- zz 已定：按 zz 原话写的方向，执行以它为准。
- 本聊方向：zz 最新定调后形成的方向，细节仍待一期跑通后再定。
- 提案或未决：Amani、会议或另一模型的说法，zz 未拍板，不得当成已定。

## 一句话

Bear-xx 只做平台。它的价值不是自带几个工作流，也不是一个更聪明的聊天框，而是让一个人把重复性工作组合成 Flow，生成一个 Bot，Bot 按同一张图执行，跑偏能定位到哪一步，改图即改 Bot 的下一版，旧任务用旧版跑完。

一个 Bot 只干一件事，干得住、改得了、查得到。

## 价值：解决什么问题

个人做自媒体难的不是生成一条片子，是每天稳定再来一条，且风格、证据、质量不漂移。

agent 加 skills 能出一条片子，但换模型、换 prompt 就可能变味，过程不可交接，出了问题也难定位。Bear-xx 把流程外化成一张图：图定顺序，节点内允许 ReAct 调工具收敛，关键处有人可干预，每一步产物和版本都有记录。

所以价值不在灵活度本身。灵活度不构成壁垒，链路可控、可观测、可交接才是。

另一模型提出的批评，本文如实保留：目前还没有第二个具体的人说过想做这种片子但做不出来。一期个人使用先成立，外部验证仍是缺口，不能用“以后会有人用”代替证据。

## 与 skill、Coze、Dify 的差异：目前仍是最高优先级未决

会议上 lyk 和陈伟正自己先问了这个问题：“这东西就跟 skill 没什么区别。”会上先搁置，未解决。

当前能给出的最诚实说法是：skill 是一次性 prompt 或能力说明，Bear-xx 是一份可审计、可复现、可版本、可交接的编排合同，外加 Bot 的身份、独立记忆和执行记录。

但这句话还不能算已证明的差异。一期必须用成品回答它：如果一期成品等价于一份 skill 加一个壳，那差异就只剩可观测的执行链路或多 Bot 协作，二者至少要做实一个。本文不把这句话写成结论。

## zz 已定的大概念

- 大概念是“什么工作流都可以自己做”，不是固定几个工作流。价值来自基建能力支撑的自由组合。
- “自己做”面向创作者和普通用户，制作者形态是人加 AI：AI 在已有节点和已有工具范围内起草 Flow 与 schema，用户看得懂地审、点头、再跑。schema 是 AI 必须遵守的合同，仍需校验与试跑。
- 扩展顺序：视频，之后是小说，再是小说改短剧。小说在 Bear-xx 上参考 aiproject 好的地方重新实现，不是照搬它的重设计。短剧是新方向，购买理由从讲明白事实变成人物与故事值得追，不能自动继承视频的验收标准。
- 参考只学思路，在自有平台重实现，不抄代码，不直接调用外部项目。Chromium、FFmpeg 这类现成原语照用。

## 四层不变

这是全项目的分类法，新能力先分桶再动手，分错桶就是屎山的开始。

- 节点等于语言，闭集。只有控制流与执行语义：开始、结束、agent、plan、plan-loop、approval、synthesize、join、loop、condition、structured-output、evaluate。加一种节点等于改语言，门槛极高，须经 zz 单独批准。
- 工具等于确定性能力，开放注册。走 CapabilityRegistry，按 toolGroups 装配。渲染、搜索、生图这类能力都在这一层。
- Flow 等于编排，特化的载体。做视频、小说、画图各是一条 Flow，画布不生产领域语义。
- Agent 与模板等于持久化专长。“视频 agent”不是新节点类型，而是保存好的 Agent（身份加绑定 Flow）加 Flow 模板。

补丁有两处，zz 已定：

- 状态与资产显性化。状态归平台管，读写走工具，改动留版本。小说与短剧共用同一套人物资产。
- 组合尺度说清。单 Flow 内组合已够用；跨 Flow 可走注册层的 subagent 口子；Flow 嵌套 Flow 是唯一可能触动闭集的点，须经 zz 单独批准。

已收回的主张，不得复活：bearxx 调 aiproject 接口；小说专用节点或薄节点壳；“每次同路”（应为关键约束明确、局部允许自主）；“Codex 只能批文件”；“不同层不用比”；把定位改成日更知识视频工作台。

## Bot 模型：平台的使用面

zz 2026-10-31 晚定调：第一版视频面向个人使用，个人通过组合好的 Flow 生成一个自媒体 Bot，Bot 去执行 Flow。

Bot 的定义：一条 Flow，加一个身份，加一份独立记忆，加一套执行记录。Flow 是 Bot 的执行定义，不是产品本身。

- 组合与生成分离。画布是编辑入口，Bot 是使用入口。日常只跟 Bot 聊天，不直接改图。
- 执行等于图定顺序加节点内 ReAct 调工具收敛，审批节点的作用是人可干预。
- Bot 间默认隔离。拉进同一群聊或被点名时才共享上下文。
- 会议里已定的群聊多 Bot、定时任务、主动执行，属于 Bot 模型的扩展方向，一期不默认包含。只有个人真的需要多个 Bot 协作时才做。

会议说“第一版不做平台化”，与 zz 的平台方向并不冲突：会议那句话是指对外不讲通用工作流编辑器、不铺多场景；zz 的平台是指底层基建与四层规范。底层是平台，使用面是 Bot。

## 可视化：两层，zz 2026-10-31 晚纠正

之前把可视化混成一层是错的。zz 纠正后，可视化分两层：

1. Bot 执行的可视化：链路可视化。跑到哪一步、哪一步失败、产物是哪个版本，都能看得到、定位得到。
2. Bot 角色产物的可视化：可扩展。不同 Bot 展示不同的业务数据，例如个人健康助手 Bot 展示健康数据图表，自媒体助手 Bot 展示选题数据、粉丝与播放量等数据。

这只是定方向。一期先做一版跑通一个流程，第二层的具体形式后面再定，不在一期里把每种 Bot 的展示都定死。

会议 D8 的做法（写死 HTML 骨架、AI 只更新一个 JSON、前端注入渲染）可作为产物可视化的一种实现思路参考，但不是 zz 已定的最终方案。第三方自媒体数据目前拿不到，短期只展示自有选题与风格类数据。

## 规范纪律：防止越堆越屎山

- 节点冻结。领域行为落 prompt、工具、Flow 模板，不落节点类型。
- 工具入库标准。全局工具须满足 schema 清晰、确定性可测、成本上限明确、负责人明确、有回归用例；模板内工具只服务一个方向，不进全局注册表。入库档位由 zz 与维护者决定。
- 产物版本化。改了图或 prompt 就是新版本，旧审批不自动带到新版本。
- 状态显性化。人物、关系、时间线、已发生事实、章节版本不能只藏在 prompt 或聊天摘要里。
- 质量门与成本门。事实错误阻断交付；成本按合格成片核算，含模型、渲染、失败重试与人工时间，要看高成本尾部，不只看平均值。具体阈值由 zz 在每个方向立项时定。
- 删除纪律。旧链路、旧类型、旧模板要立删除期限，到期延期须有具体阻塞证据。
- 发布在 Flow 之外。平台只交付到待发布成片，发布、选标题、定时间、加 BGM 由用户自己做。
- 不做清单：不做通用编码 agent，不做完整多轨剪辑器，不做自动发布与跨平台运营调度，一期不做 Bot 市场与多业务首页，不同时铺小说和短剧。

## 发展路线

1. 一期：个人自媒体 Bot 跑通 vibe 视频这一条 Flow，证明同一套机制不改底层就能再出下一条片。
2. 二期方向：同一 Bot 模型扩到小说 Bot，再到短剧 Bot。扩的是 Bot 的种类，不是多业务首页。
3. 再往后：只有个人真的需要多个 Bot 协作时，才做群聊协作、定时与主动执行。
4. 始终不做的事：用灵活度当壁垒，用模板数量、工具数量、Agent 数量当成绩。

## 调研背景：只作输入，不作目标

2026-10-31 逐仓库页实证：四路合计尝试 124 个项目，实际打开 111 页，未打开 13 个，去重后仍超 100 个。结论只是研究输入，未拍板定位。

可用的背景判断有三条：通用平台与通用工作台都很拥挤；“数字有来源”不是无人区，只是验收标准，不是护城河；集市信任成本很高，一期不开集市。

另一模型的独立判断，zz 未拍板接受：收敛成一条链方向对，但“样板”本身不等于解决别人的真问题；bearxx 与 agent 加 skills 的差异只对长期跑生产线的团队值钱，对只想出片的个人可能是更重更慢的负分；对方建议先封存“换热度”这个任务、把设计取舍翻译成求职材料，而不是删除项目。本文记录该判断，不采纳为决定。
