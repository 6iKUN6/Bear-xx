# RBAC、会员等级与智能体开放策略设计

**日期：** 2026-09-01
**状态：** 已实现
**对应：** GitHub issue #7（范围扩展）
**范围：** 后台两级管理员、独立后台登录、终端用户会员等级与到期、智能体展示及会员门槛、管理审计、Admin 管理界面和小程序锁定展示。
**不包含：** Flow 资源级分享、可配置会员档位、支付与自动续费、会员订单、密码重置、独立管理员账号体系、Web/Desktop 界面适配。

## 目标

在复用现有 `User` 身份的前提下，建立两条彼此独立的权限轴：

1. **后台管理权限**：区分顶级管理员与次级管理员，后端对每项管理操作做最终授权。
2. **终端用户权益**：按固定会员等级限制智能体使用，同时支持会员到期和客户端锁定展示。

当前只交付小程序界面，但会员与智能体资格属于服务端领域能力，后续 Web、Desktop 客户端复用同一套接口和判定，不各自实现等级算法。

## 已确认决策

- 第一版只做角色级 RBAC，不做 Flow 或其他资源级授权。
- 管理员与终端用户共用 `User`；管理员角色和会员等级互不推导。
- 后台角色固定为 `USER / ADMIN / SUPER_ADMIN`。
- 会员等级固定为 `FREE / PLUS / PRO`，支持可空到期时间。
- 智能体采用最低会员等级，不做逐用户白名单。
- 智能体的“展示”“启用”“最低会员等级”是三个独立概念。
- `visible=false` 只退出客户端发现列表，不影响已有会话或持有智能体 ID 的合资格用户。
- 会员不足的可见智能体仍在客户端展示，但锁定聊天入口并说明所需等级。
- 现有管理员保留账号和密码哈希，升级为 `SUPER_ADMIN`；本期不实现密码重置。
- 只有已具备 `username + passwordHash` 的用户可被授予管理员角色。
- 系统始终至少保留一名 `SUPER_ADMIN`。
- Admin 调试可以绕过会员等级，但不能调试已停用智能体。
- 角色、会员和智能体开放策略的人工变更必须记录真实操作者和前后值。

## 领域边界

### 后台角色

| 能力 | `ADMIN` | `SUPER_ADMIN` |
| --- | --- | --- |
| 可观测、任务、错误、调试 | 允许 | 允许 |
| 管理用户会员 | 允许 | 允许 |
| 管理智能体 | 允许 | 允许 |
| 管理和发布 Flow | 允许 | 允许 |
| 管理模型预设及密钥 | 禁止 | 允许 |
| 管理未来系统配置 | 禁止 | 允许 |
| 授予、调整、撤销管理员角色 | 禁止 | 允许 |

管理员角色不影响工具风险等级。`requiresApproval` 仍只由 `CapabilityRegistry` 推导；后台身份、会员等级和 Flow JSON 均不能降低工具审批要求。

### 会员资格

显式定义等级顺序：

```txt
FREE < PLUS < PRO
```

不得依赖 Prisma 枚举的字符串顺序或数据库排序实现等级比较。

用户的当前有效等级按请求时刻计算：

```txt
effectiveTier =
  membershipExpiresAt 不为空且已到期
    ? FREE
    : membershipTier
```

到期不会清空配置字段。Admin 同时展示配置等级、有效等级和到期状态，使运营人员能区分“配置为 PRO 但已过期”和“配置为 FREE”。

### 智能体状态

- `enabled`：是否允许执行。为 `false` 时任何终端用户和 Admin 调试都不能启动。
- `visible`：是否进入客户端发现/选择列表。为 `false` 时不影响已有会话、历史回显或持 ID 访问。
- `minimumMembershipTier`：使用该智能体所需的最低有效会员等级。

资格判定统一为：

```txt
canUse =
  agent.enabled
  && effectiveTier >= agent.minimumMembershipTier
```

`visible` 不参与 `canUse`。客户端隐藏不是权限控制，后端必须在任务执行入口重新判定。

全局默认智能体必须始终满足：

```txt
enabled = true
visible = true
minimumMembershipTier = FREE
```

## 数据模型

### User

扩展现有 `UserRole`：

```txt
USER
ADMIN
SUPER_ADMIN
```

`User` 新增：

- `membershipTier MembershipTier @default(FREE)`
- `membershipExpiresAt DateTime?`

新增固定枚举：

```txt
MembershipTier = FREE | PLUS | PRO
```

不新增 `AdminAccount`。同一个人可以同时拥有管理员身份和会员权益，但两者分别判断、分别审计。

### Agent

新增：

- `visible Boolean @default(true)`
- `minimumMembershipTier MembershipTier @default(FREE)`

保留现有 `enabled` 和 `isDefault` 语义。默认值保证存量智能体升级后仍然展示且对所有用户可用。

### 管理审计

新增统一的管理审计模型，覆盖当前范围内的权限和权益变更。每条记录至少包含：

- `actorId`：人工操作必须为真实管理员；系统 bootstrap 为 `null`。
- `targetType`、`targetId`：目标用户或智能体。
- `action`：角色修改、会员修改、智能体开放策略修改等闭集动作。
- `before`、`after`：仅保存本次允许审计的安全字段快照。
- `createdAt`。

审计快照禁止包含密码及密码哈希、JWT、第三方密钥、Cookie 或其他凭据。人工写操作的数据更新和审计写入必须处于同一事务，不能出现“数据已改但审计缺失”。

现有 `AgentFlowAuditLog` 继续记录 Flow 域动作，不迁移、不复制到通用审计表。

## 管理员安全护栏

- 只有 `SUPER_ADMIN` 可以修改管理员角色。
- 操作者不能修改自己的管理员角色。
- 不能降级或撤销系统中最后一个 `SUPER_ADMIN`。
- 被提升的用户必须同时具备非空 `username` 和 `passwordHash`。
- 角色修改在可串行化事务中重新读取目标、操作者和超管数量，再执行护栏、更新和审计，避免并发操作同时移除最后一个超管。
- 事务内必须再次确认操作者仍是 `SUPER_ADMIN`，不能只依赖事务外已通过的 Guard，避免角色在请求处理中被并发降级后仍完成高权限写入。
- `RolesGuard` 继续按请求实时查库，不从旧 JWT 读取角色；降级后立即失去相应后台权限。
- 前端隐藏导航和禁用按钮只改善体验，直接访问路由或调用 API 仍由后端返回 403。

## 管理员初始化与 seed

当前弱口令来自 `apps/api/prisma/seed.ts` 的默认回退 `admin / admin12345`，并非认证服务写死。

调整后：

- 删除 seed 的默认管理员账号和默认密码。
- 仅在同时明确提供 `ADMIN_USERNAME` 与 `ADMIN_PASSWORD` 时才允许 seed 创建一个初始 `SUPER_ADMIN`；缺任一项时明确跳过管理员创建，但继续维护默认智能体。
- seed 不再反复覆盖已存在用户的管理员角色。
- 新增幂等的一次性本地 bootstrap 命令，把所有现有 `ADMIN` 提升为 `SUPER_ADMIN`，保留账号、密码哈希和密码更新时间。
- bootstrap 记录 `actorId=null` 的系统审计，且不输出密码、密码哈希或令牌。
- 本次不重置现有管理员密码，不创建或回传明文凭据。

Prisma 迁移只由 `schema.prisma` 生成。实现阶段不手写或编辑 `migration.sql`；schema 迁移和 bootstrap 命令由用户分别在本地执行。

## 认证与授权接口

### 独立后台登录

新增：

```txt
POST /admin/auth/login
```

该接口：

- 只查询已存在的 `username + passwordHash` 用户。
- 只允许 `ADMIN` 或 `SUPER_ADMIN` 登录。
- 账号不存在、密码错误或不是管理员时返回统一的后台登录失败信息，不泄露账号是否存在。
- 绝不自动注册普通用户。
- 返回管理员基本信息和当前 `adminRole`，供 Admin 导航与按钮投影。

现有 `/auth/account/login` 保留普通客户端现状，不作为后台登录入口。Admin 登录页改用新端点。

### 权限声明

角色 decorator 使用 Prisma 闭集类型，不继续接受任意字符串。所有管理端点显式声明允许角色：

- 日常业务端点：`ADMIN`、`SUPER_ADMIN`。
- 模型预设、管理员角色、未来系统配置：仅 `SUPER_ADMIN`。

管理端 profile/会话探测应返回真实管理员角色，不再通过访问 overview 猜测“是不是管理员”。

## 用户管理 API

新增 `/admin/users` 控制面：

| 方法与路径 | 权限 | 行为 |
| --- | --- | --- |
| `GET /admin/users` | `ADMIN` / `SUPER_ADMIN` | 分页搜索用户，返回账号状态、角色、配置会员、有效会员和到期状态 |
| `PATCH /admin/users/:id/membership` | `ADMIN` / `SUPER_ADMIN` | 修改固定会员等级和可空到期时间 |
| `PATCH /admin/users/:id/admin-role` | `SUPER_ADMIN` | 授予、调整或撤销后台角色，执行超管护栏 |
| `GET /admin/audit-logs` | `ADMIN` / `SUPER_ADMIN` | 分页读取安全管理审计记录 |

列表搜索至少支持用户 ID、昵称、账号和手机号；响应对手机号等个人信息采用满足管理目的的最小字段，不返回密码状态以外的认证机密。

会员更新语义：

- `membershipExpiresAt=null` 表示永久。
- 非空到期时间必须是有效时间值；允许运营配置未来到期时间。
- 配置已到期时间不会被伪装成仍有效，响应同时给出 `effectiveMembershipTier`。
- 更新前后值与操作者在同一事务写审计。

## 智能体 API 与资格投影

### 终端接口

`GET /agents`：

- 只返回 `visible=true` 的智能体。
- 不过滤会员不足的智能体。
- 每项返回 `minimumMembershipTier`、服务端计算的 `canUse` 和结构化锁定原因。
- `enabled=false` 但 `visible=true` 的智能体仍返回并展示为“暂不可用”；展示与可执行保持独立，不以从列表消失代替停用状态。

`GET /agents/:id`：

- 允许读取隐藏智能体的安全展示详情，以支持已有会话和历史入口。
- 返回当前用户对应的资格投影。
- 不因隐藏而伪装成不存在；不存在的智能体仍返回 404。

资格响应使用结构化字段区分：

- `canUse=true`。
- `canUse=false, reason=DISABLED`。
- `canUse=false, reason=MEMBERSHIP_EXPIRED, requiredTier=PLUS|PRO`：用户配置等级本可满足，但会员已到期。
- `canUse=false, reason=MEMBERSHIP_REQUIRED, requiredTier=PLUS|PRO`。

客户端直接消费服务端结论，不自行比较等级。

### Admin 接口

管理后台不再消费终端 `/agents` 写接口，新增或迁移为 `/admin/agents`：

- 列表和详情返回全部智能体及原始管理配置。
- 创建、更新、删除、设默认允许 `ADMIN` / `SUPER_ADMIN`。
- 修改 `enabled`、`visible`、`minimumMembershipTier` 或 `isDefault` 时，在同一事务检查默认智能体约束并写管理审计。
- 默认智能体不能隐藏、停用或提高最低会员等级。

## 执行期强制校验

新增单一资格服务，负责：

1. 计算用户当前有效会员等级。
2. 读取智能体启用状态和最低等级。
3. 返回结构化资格结果，或为执行入口抛出明确 403。

以下入口必须复用该服务，不能各自复制等级比较：

- 创建单聊。
- 创建群聊及其初始成员。
- 向群聊添加智能体。
- 普通聊天直接提交 `agentId`。
- 默认智能体回落。
- 群聊自动路由选出最终回答智能体之后。
- 创建 `StreamTask` 和冻结 AgentFlow 运行快照之前。

会话创建时的校验不能代替任务创建时的校验。会员降级、到期、智能体停用或门槛提高后，历史会话和消息仍可读取，但下一次发送必须按当前事实重新判断并返回 403。

对未显式指定智能体的普通聊天，默认回落必须选中符合默认约束的智能体；若数据库事实违反约束，应明确失败并暴露运维问题，不静默回落到受限或停用智能体。

Admin `/admin/agent-tests` 绕过会员等级，但仍要求目标智能体 `enabled=true`。该绕过只存在于管理调试路径，不影响管理员本人的普通聊天，也不改变工具审批。

## Admin 界面

### 登录与导航

- 登录页调用 `/admin/auth/login`。
- 登录态保存服务端返回的管理员角色。
- 导航和路由依据角色投影：`ADMIN` 不显示模型密钥、管理员角色和未来系统配置入口。
- 权限不足的直接路由访问显示明确无权限状态，不跳成空页面。

### 用户与权限页面

新增“用户与权限”页面：

- 分页搜索用户。
- 展示昵称、账号状态、管理员角色、配置会员、有效会员、到期时间和过期标记。
- `ADMIN` 可调整会员等级与到期时间。
- `SUPER_ADMIN` 额外可从具备账号密码的用户中授予 `ADMIN/SUPER_ADMIN` 或撤销后台角色。
- 当前操作者、无账号密码候选、最后一个超管的危险操作禁用并说明原因。
- 展示管理审计记录的操作者、目标、动作、前后安全值和时间。

### 智能体管理

智能体表单和列表增加：

- “客户端展示”开关。
- 最低会员等级选择器。
- 与现有“启用”独立的三个状态展示：启用/停用、展示/隐藏、FREE/PLUS/PRO 门槛。
- 默认智能体的非法修改入口禁用，并展示默认智能体约束。

## 小程序闭环

### 用户会员状态

用户 profile/auth 契约增加：

- 配置会员等级。
- 当前有效会员等级。
- 可空到期时间。
- 是否已过期。

小程序不自行根据本机时间提升权限；展示可以使用到期时间，但最终使用资格完全服从服务端 `canUse` 和任务接口结果。

### 智能体发现与详情

- 发现列表保留所有 `visible=true` 的会员受限智能体。
- 锁定项展示所需 `PLUS/PRO`，不能进入聊天选择、群聊成员选择或 `@` 候选。
- 用户仍可进入锁定智能体详情查看完整介绍。
- 详情页聊天入口禁用，并显示“需要 PLUS/PRO，当前暂不支持自助升级”。
- 不新增不可购买的会员升级占位页。
- 隐藏智能体不进入发现列表，但已有会话继续显示其名称、头像和历史消息。

### 错误呈现

后端 403 是最终事实源。小程序需要区分：

- 会员等级不足。
- 会员已到期。
- 智能体已停用。

不得把这些错误捕获为空列表、网络失败或默认成功。用户在页面停留期间发生权限变化时，发送失败应更新本地资格并显示服务端原因。

## 错误处理与并发

- 账号不存在、后台密码错误、非管理员使用后台登录统一返回未授权文案，避免账号枚举。
- 资格不足返回 403 和稳定业务码，客户端不靠中文字符串分支。
- 用户、智能体不存在返回 404；配置非法返回 400；权限不足返回 403。
- 最后一个超管护栏和默认智能体护栏必须在可串行化事务内判断，不能先查后改留下竞态。
- 到期比较统一使用服务端当前时间，边界定义为 `expiresAt <= now` 即已过期。
- 审计写入失败时整个管理变更回滚。
- 角色和会员变更不要求重新签发 JWT；守卫和资格服务实时读库保证即时生效。

## 迁移与发布顺序

本功能按三个可独立验证的阶段实施，降低跨端改动风险：

### 阶段 1：管理员 RBAC

- 扩展 `UserRole`、新增管理审计模型。
- 新增后台登录和角色守卫闭集。
- 增加用户管理、角色护栏与 Admin 角色感知。
- 删除 seed 默认弱口令，增加现有管理员 bootstrap 命令。

### 阶段 2：会员与智能体强制权限

- 增加会员字段、智能体展示和最低等级字段。
- 实现统一资格服务、Admin 会员/智能体管理及审计。
- 在会话、路由、任务创建和默认回落链路接入强制校验。

### 阶段 3：小程序闭环

- 更新 OpenAPI 并重新生成移动端客户端。
- 展示会员状态、智能体锁定状态和详情禁用入口。
- 回归单聊、群聊、历史会话和权限实时变化。

各阶段在同一功能分支内保持可单独 review 的提交。数据库 schema 由 Agent 修改，迁移命令和 bootstrap 命令由用户本地执行。

## 测试与验收

### API 单元与集成测试

- 后台登录：管理员成功；普通用户、未知账号、错误密码均失败且不自动注册。
- 角色矩阵：`ADMIN` 不能管理管理员、模型预设和系统配置；`SUPER_ADMIN` 可以。
- 超管护栏：自身角色修改、最后一个超管降级/撤销、无账号密码用户提升均被拒绝。
- 并发修改不会同时移除最后一个超管。
- 会员边界：永久、未到期、`expiresAt = now`、已到期均得到正确有效等级。
- 资格矩阵：FREE/PLUS/PRO 对三档智能体完整覆盖；停用优先于会员资格。
- 默认智能体不能隐藏、停用或提高门槛。
- `visible=false` 不影响持 ID 的合资格使用和历史读取。
- 会话创建、群成员增加、直接聊天、默认回落、群聊路由、任务创建均不能绕过门槛。
- 降级、到期或提高门槛后，历史可读但下一次发送被拒绝。
- Admin 调试绕过会员等级但拒绝停用智能体。
- 角色、会员和智能体策略修改均生成无敏感信息审计；审计失败导致业务变更回滚。
- seed 未配置管理员变量时不创建弱口令账号，bootstrap 保留原密码哈希并幂等升级角色。

### Admin 验收

- `ADMIN` 与 `SUPER_ADMIN` 登录后看到各自允许的导航和操作。
- 用户搜索、会员等级和到期时间编辑结果与有效等级一致。
- 最后一个超管和当前用户的角色操作有明确禁用原因。
- 智能体三个状态独立展示，默认智能体非法操作不可提交。
- 直接请求无权 API 返回 403，而不是只靠按钮隐藏。

### 小程序验收

- 可见但受限的智能体显示锁定等级，可查看介绍但不能开始聊天。
- PLUS/PRO 到期后无需重新登录，下一次发送立即被拒绝并显示正确原因。
- 隐藏智能体退出发现列表，但已有会话、头像和消息仍正常显示。
- 免费默认智能体始终可用。
- 群聊成员选择和 `@` 候选不能选择无资格智能体。
