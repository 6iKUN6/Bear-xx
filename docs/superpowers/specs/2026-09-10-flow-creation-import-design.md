# Flow 创建与 JSON 导入设计

## 目标

在 Flow 列表现有“新建 Flow”入口中同时支持模板创建和 JSON 导入，并允许管理员在创建成功后直接进入新草稿画布。创建行为继续复用现有 `POST /admin/agent-flows`，不新增后端接口、数据库字段或兼容层。

## 交互

新建弹窗包含两个模式：

- **模板创建**：保留现有模板选择、名称和描述编辑。
- **JSON 导入**：支持选择本地 `.json` 文件或直接粘贴完整 Flow Definition；两种输入进入同一文本编辑区。

JSON 模式解析成功后，从 Definition 读取名称和描述并允许管理员覆盖。覆盖只修改顶层 `name` 与 `description`，其余字段原样提交。切换模式时不混用两个模式的输入状态；关闭弹窗后清空本轮状态。

弹窗底部提供两个创建动作：

- **创建**：创建成功后关闭弹窗并留在 Flow 列表。
- **创建并编辑**：创建成功后使用响应中的 `flow.id` 和 `draftVersion.id` 进入 `/flows/:flowId/versions/:versionId/edit`。

创建进行中禁用模式切换、输入与关闭操作，避免重复提交或跳转到错误草稿。

## 数据流与错误

模板模式由前端复制模板 Definition，再覆盖顶层名称和描述。JSON 模式先执行本地语法和对象根校验，再覆盖名称和描述，最后调用现有创建 mutation。

错误分工保持单一：

- JSON 语法、数组或标量根值由弹窗就地提示，不发请求。
- Definition schema、节点、边与图结构是否合法由后端现有校验器裁定。
- 后端拒绝时保留弹窗和全部输入，并展示原始错误摘要。
- 文件读取失败、文件类型不符或空文件在弹窗内明确提示。

## 实现边界

- 修改 `FlowCreateDialog` 的模式、文件读取、文本解析和双动作回调。
- 修改 `FlowsPage` 接收完整 Definition 和创建意图，并在需要时导航到编辑器。
- 抽出可独立测试的 JSON 创建输入解析函数。
- 不修改 AgentFlow API、Prisma schema、执行器或 Flow Definition 契约。

## 验证

- 模板创建仍能覆盖名称和描述。
- 粘贴 JSON 和选择文件走相同解析路径。
- 非法 JSON、非对象根值和空输入不会请求后端。
- “创建”留在列表，“创建并编辑”进入返回草稿的编辑地址。
- 执行 Admin typecheck、lint、build 和相关单元测试。
